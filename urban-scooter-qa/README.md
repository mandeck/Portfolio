# Urban Scooter — QA Testing Project

## Project Overview

This project was completed as part of the TripleTen QA Engineering program. It involved testing the Urban Scooter application across web, mobile, and API environments.

The work focused on analyzing requirements, preparing and executing test cases, documenting results, and identifying defects.

## Testing Scope

### 1. Web Application Testing

- Analyzed requirements and prepared test cases for the web application.
- Executed 66 test cases using Chrome and Opera.
- Documented actual results and identified discrepancies between expected and actual behavior.
- Recorded defects discovered during testing.

**Results:**
- Chrome: 55 passed, 11 failed.
- Opera: 55 passed, 11 failed.

### 2. Mobile Application Testing

- Prepared and executed test cases on a Pixel 5 emulator running Android 12 (API 31).
- Tested application behavior, notifications, application states, and connectivity.
- Documented results and identified defects.

**Results:**
- 15 passed
- 17 failed
- 3 skipped

### 3. API Testing

- Used Postman to test courier creation, deletion, and related API behavior.
- Evaluated response status codes, response messages, parameters, and negative scenarios.
- Documented expected and actual results.

**Results:**
- 8 passed
- 1 failed

## Tools & Technologies

- **Postman** — API testing
- **Chrome and Opera** — Web application testing
- **Android Studio Emulator** — Mobile application testing
- **Jira** — Defect tracking
- **Microsoft Excel** — Test case documentation and test results

## Project Deliverables

The `test-cases` folder contains a consolidated Excel workbook with three worksheets:

- Web Testing
- Mobile Testing
- API Testing

The testing folders contain supporting evidence and documentation as available.

## Notes

This project was completed in a training environment as part of the TripleTen QA Engineering program. Test results reflect the execution outcomes documented during the project. Failed tests represent discrepancies identified during testing and are not presented as successful test executions.
